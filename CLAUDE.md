Packages that Turbopack doesn't bundle must end up in `.next/standalone/node_modules` (today `pg` and `tedious`; `tarn` is bundled); filesystem calls on runtime paths need `/* turbopackIgnore: true */`. `next.config.ts` keeps `tedious` in `serverExternalPackages` (Turbopack fails on its `@azure/identity` chain otherwise); in a Vercel build (`VERCEL` set) `tedious`/`tarn` are aliased to `src/lib/db/zonder-mssql.ts` and excluded from tracing, so Vercel functions never carry the driver.

`next build` does not run ESLint in Next 16, so lint errors don't block a deploy. Run `npm run lint` on its own. There is no UI test suite; `db:test` covers the data layer and only accepts a local database; `test:unit` covers config parsing, error scrubbing, the migration runner, the strict mssql plugin and the SQL Server search parser. Env vars (see `.env.example`): `DB_DIALECT` (`postgres` | `mssql`), `AUTH_DRIVER` (`supabase` | `local`), `STORAGE_DRIVER` (`supabase` | `database` | `filesystem`), `DATABASE_URL` (direct Postgres connection; Vercel: Supabase **transaction pooler**, port 6543), Supabase vars (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, the last only used by `db:vergelijk`), `NEXT_PUBLIC_SITE_URL`, `MAIL_ENCRYPTION_KEY`; for an own-login install also `SITE_URL`, `BETTER_AUTH_SECRET` (≥32 chars, also signs upload tickets), `REGISTRATIE` (`open` | `uitnodiging`), `STORAGE_DIR` (must be absolute), `DB_AUTO_MIGRATE`. SQL Server reads `MSSQL_SERVER` (SSMS forms `host`, `host\INST`, `host,port`, `tcp:host,port`), `MSSQL_PORT`, `MSSQL_INSTANCE`, `MSSQL_DATABASE`, `MSSQL_AUTH` (`sql` | `ntlm` | `azure-default`), `MSSQL_USER`, `MSSQL_PASSWORD`, `MSSQL_DOMAIN`, `MSSQL_AZURE_CLIENT_ID`, `MSSQL_ENCRYPT` (`true` | `false` | `strict`), `MSSQL_TRUST_SERVER_CERT` (default true unless `MSSQL_CA`, `MSSQL_TLS_SERVERNAME` or strict), `MSSQL_CA`, `MSSQL_TLS_SERVERNAME`, plus `DATABASE_POOL_MAX`; only when `DB_DIALECT=mssql` (a bad `MSSQL_*` can never break a Postgres install), and `DATABASE_URL` is then ignored. Config is parsed and validated in `src/lib/config.ts` (it rejects impossible combinations, e.g. supabase login + database storage, folder storage on Vercel, SQL Server on Vercel or with supabase login, a port plus an instance, `MSSQL_ENCRYPT=false` to a non-loopback host); never read backend choices from `NEXT_PUBLIC_*`.

Local dev: `.env.local` points `DATABASE_URL` at the **local copy** (`npm run db:lokaal`), while login still goes through the production Supabase Auth and uploads go to the production Storage buckets. `MAIL_ENCRYPTION_KEY` must be identical in `.env.local` and in Vercel. `PROD_DATABASE_URL` (session pooler, port 5432) is only for `db:backup`. The local database must use a real locale (not `C`): `LC_CTYPE` decides how full-text search splits words.

## Architecture

### Route groups (`src/app`)
- `(auth)`: public login, registration, password-reset and invitation pages, in a centered layout.
- `(dashboard)`: the authenticated app. `layout.tsx` calls `requireUser()` (identity + `profiles` row) and passes the profile to `DashboardShell` (sidebar, topbar, `ThemeSync`). Only `<main>` scrolls. The topbar always stays visible.
  - A page can put its own buttons in the topbar with `<TopbarActions>` from `src/components/layout/topbar-actions.tsx`, which portals them into a slot. The article page does this. The slot is hidden below `md`, so a page needs its own mobile fallback (see `article-header.tsx`). On the dark topbar, use `topbarButtonClass`.
- `(print)`: a bare layout for `/artikelen/[slug]/afdrukken` (print / save as PDF). It uses the `.print-light` class to force light colors.
- `/` redirects to `/artikelen`. `/api/auth/callback` exchanges the Supabase auth code for a session.

### Auth and authorization
- `src/proxy.ts` (Next 16's name for middleware; it **must live in `src/`** because the app dir is `src/app` — the old root `middleware.ts` was never executed) calls `handleProxy` → `updateSession` in `src/lib/supabase/middleware.ts`. That refreshes the session with `getClaims()` and redirects. **Default-deny**: every page needs a login except the paths in `src/lib/auth/paths.ts` (`AUTH_PAGINAS`, `OPEN_PAGINAS`); a new public page must be added there. The matcher skips `/api/`, `_next` and image files (keep the `\\.` escape in the matcher string).
- **RLS no longer protects app queries**: the app connects directly as the database owner. Authorization lives in `src/lib/auth/index.ts`: `getCurrentUser()` (cached per request), `requireUser()` / `requireAdmin()` for pages (redirect), and `NIET_INGELOGD` / `GEEN_BEHEERDER` results for actions. **Every exported function in a `"use server"` file is callable by anyone as a server action, so each one must check `getCurrentUser()` itself** (and `is_admin` for admin functions), also read-only ones.
- The login system is behind `AuthDriver` (`src/lib/auth/types.ts`): `supabaseAuth` (`src/lib/auth/supabase.ts`) or `localAuth` (`src/lib/auth/local.ts`, Better Auth). The only Supabase clients left are `src/lib/supabase/server.ts` (auth + storage, cookie-based) and the proxy client in `middleware.ts`.
- **Own login (Better Auth 1.7)**: options in `src/lib/auth/better-auth-opties.ts` (shared with scripts), instance in `better-auth.ts` (shares `getDb()`, `transaction: true`, tables `auth_users`/`auth_sessions`/`auth_accounts`/`auth_verifications` with camelCase columns, uuid ids from Postgres, `nextCookies()` last). Sign-in/up/out go through server actions calling `auth.api.*`; the HTTP routes in `src/app/api/auth/[...all]/route.ts` only allow `get-session` and `sign-out`. Because `auth.api` calls are not rate limited by Better Auth, `local.ts` limits failed logins itself (per IP+email, IP, email; the IP is the **last** `X-Forwarded-For` entry, because earlier entries are client-chosen). The proxy only checks the session cookie exists (`getSessionCookie`); pages validate. `SessionRefresher` (rendered last in the dashboard layout) calls `/api/auth/get-session` so sessions get extended. The profile is created in `localAuth.signUp`, with a lazy fallback in `getCurrentUser`; the **oldest `auth_users` row** becomes admin. With `REGISTRATIE=uitnodiging` only the very first account may register without invitation.
- **Password reset** with own login: an admin creates a link in Beheer → Gebruikers (`createPasswordResetLink`, table `password_resets`, 7 days, single use, a new link revokes older ones); `/wachtwoord-herstellen/[token]` sets the password via Better Auth internals (`setPassword` in `local.ts`) and deletes all sessions. With Supabase: unchanged email flow.
- Permissions model: any authenticated user can create, edit and delete any article or tag. Admin-only: invitations and user management (`src/actions/admin.ts`). Supabase: the `handle_new_user` trigger on `auth.users` creates the profile; the first user becomes admin.
- Invitations are rows with a random token (generated by the app). The admin UI copies the `/uitnodiging/<token>` link to the clipboard, and the admin shares it by hand. The app sends no email. The invitation page looks the token up on the server (no login needed).

### Data layer
- Server Actions in `src/actions/*.ts` check auth and call repositories in `src/lib/db/repositories/*.ts` (Kysely). Server components also call the actions as plain functions, for example `getArticles` and `getArticleBySlug`. Mutations return `ActionResult<T>` (`{ success, data?, error? }`), catch DB errors into a Dutch message and call `revalidatePath`.
- `getDb()` (`src/lib/db/index.ts`) is a per-process singleton built by `maakKysely()` (`src/lib/db/connection.ts`): a `pg` pool for Postgres (`attachDatabasePool` on Vercel), or for `mssql` the lazy dialect in `src/lib/db/mssql-dialect.ts`, which imports `tedious`/`tarn` only in `Driver.init()` (first query), so Postgres installs never load the driver. Idle connections are kept 5 s on Vercel (attachDatabasePool keeps the function alive via `waitUntil` for the idle time, which is billed as provisioned memory) and 60 s when self-hosted; `pool.on("error")` keeps a dropped idle connection from crashing the process. Table types: `src/lib/db/schema.ts`; repositories map rows to the hand-written types in `src/types/index.ts`.
- Write repositories so they work on Postgres **and** SQL Server (helpers in `src/lib/db/dialect.ts`): app-generated ids (`randomUUID`), set `updated_at` in the app (SQL Server has no triggers), JSON columns written as a **string** and read with `parseJson`, timestamps returned as ISO via `toIso`, unique violations via `isUniqueViolation` (also unpacks the **arrays** of errors Kysely-mssql throws; `losseFouten`/`foutNummers` for SQL Server error numbers, `isMssqlDeadlock` for 1205), pagination with `.orderBy(..., "id").offset().fetch()` (no `limit`), no `returning()`, multi-step writes in `getDb().transaction()`. **Never `selectAll()` on `articles`** (it would pull the generated `search_vector`, or on SQL Server the computed `search_text`).
- Modules used by `scripts/` (`config.ts`, `db/connection.ts`, `db/mssql-dialect.ts`, `db/mssql-controles.ts`, `db/migrate.ts`, `db/guard.ts`, migrations) must not import `server-only`. Scripts run with `tsx` (`.mts`); those importing repositories use `--conditions=react-server`.
- Migrations for non-Supabase installs: TS modules in `src/lib/db/migrations/<dialect>/` (`0001_basis` = the public tables, `0002_auth` = on Postgres exactly what Better Auth's `getMigrations` generates, `0003_password_resets`, `0004_files`; mssql also `0005_fulltext`), run by `migreer()` via `npm run db:migrate` or `DB_AUTO_MIGRATE=true` (`src/instrumentation.ts` → `src/lib/db/auto-migrate.ts`; never on a Vercel preview, and after a connection error it retries every minute in the background). A migration may return `"overgeslagen"`: it is logged and **not** recorded in `kb_migrations`, so it runs again later (used by `0005_fulltext` when the server has no Full-Text Search). When Better Auth options change, regenerate/compare with `getMigrations` from `better-auth/db/migration` (on SQL Server `test:login:mssql` asserts it reports nothing to create or add). The Supabase install keeps `supabase/migrations/` (manual, with approval).

### SQL Server (`DB_DIALECT=mssql`)
- **Postgres must stay byte-identical.** Both live installs are Postgres. Every shared change is either a provable no-op on Postgres or sits behind `getConfig().db.dialect === "mssql"`; never rewrite Postgres SQL to make it "dialect-neutral" (e.g. `search.ts` keeps `zoekPostgres` verbatim, `storage/database.ts` keeps `substring(… FROM … FOR …)`).
- Only self-hosted with own login (`AUTH_DRIVER=local`); config refuses it on Vercel. SQL Server 2016+ (`ProductMajorVersion >= 13`); Azure SQL (`azure-default`) and NTLM are untested.
- Schema (`src/lib/db/migrations/mssql/`): all DDL is raw `sql` with `dbo.`-qualified tables, double-quoted columns, named constraints (`PK_`/`UQ_`/`FK_`/`DF_`/`CK_`), idempotent via `IF OBJECT_ID(...) IS NULL` (Kysely's `.ifNotExists()` compiles to invalid T-SQL), one batch per template, no `GO`, no `${param}` in DDL. Ids and FKs are **`nvarchar(36)`** (tedious sends every JS string as nvarchar; `varchar` would cause `CONVERT_IMPLICIT` scans, `uniqueidentifier` returns uppercase ids). JSON in `nvarchar(max)` with `ISJSON` checks, booleans `bit`, timestamps `datetime2(3)` with `SYSUTCDATETIME()`, files `varbinary(max)`. `articles.reviewer_id` and `password_resets.created_by` are NO ACTION (SET NULL gives Msg 1785, multiple cascade paths).
- **No triggers on SQL Server tables** (Better Auth writes with `OUTPUT inserted.*`, Msg 334; triggers also break row counts). Server option NOCOUNT (`user options` bit 512) breaks `numUpdatedRows`; `/status` treats it as fatal.
- Raw mssql SQL always qualifies tables with `dbo.`; never select `search_text`; never `Promise.all` on one transaction or connection (tedious `EINVALIDSTATE`); no `COUNT_BIG`, `bigint` or `decimal` results (tedious returns strings); no `sql.lit` for text or booleans (no `N''` prefix, `true` is invalid).
- Keep the tedious options in `mssql-dialect.ts`: `useUTC: true` (Better Auth writes ISO strings with `Z`), `DateTime` mapped to `DateTime2` (else 1/300 s precision), `abortTransactionOnError: false` plus the rollback wrapper (else error 3903 masks the real error), and do **not** set `enableArithAbort`, `enableQuotedIdentifier`, `useColumnNames`, `rowCollectionOn*` or `lowerCaseGuids` (the defaults are load-bearing: Kysely quotes with `"`, the persisted computed column needs ARITHABORT/QUOTED_IDENTIFIER). Request timeout 60 s (migrations 300 s, because of `sp_getapplock … 60000`).
- `src/lib/db/mssql-bewaker.ts`: a strict Kysely plugin, active only when `NODE_ENV !== "production"`, that throws on constructs Kysely compiles to invalid T-SQL (`.limit()`, `.fetch()` without `.offset()`, `returning`, `onConflict`, row locks, `ifNotExists`, …).
- Search (`src/lib/db/search/mssql.ts`, parser `mssql-query.ts`): `CONTAINSTABLE` on the persisted computed column `search_text` (title + excerpt + content_text; `0005_fulltext`, catalog `kb_fulltext`, LCID 1043, `STOPLIST = OFF`, `CHANGE_TRACKING AUTO`) with title/excerpt bonus ranks; without an active full-text index, or for 5 minutes after a full-text error, a `LIKE` fallback (`COLLATE Latin1_General_100_CI_AI`, crude `-en`/`-s` stem). The index check is cached 5 minutes per process. Accepted differences are documented in `docs/installatie.md` (E).
- Health: `src/lib/db/mssql-controles.ts` (version, NOCOUNT, collation, RCSI, full-text) feeds `/status` (row "Zoeken", warnings; never version or collation) and `db:mssql:controle`. `veiligeFoutmelding` (`src/lib/db/opstartstatus.ts`) scrubs server, instance and login names from tedious errors only; Postgres messages are unchanged.
- Recommended database: collation `Latin1_General_100_CI_AS_SC_UTF8` (2016/2017: `…_CI_AS_SC`), `READ_COMMITTED_SNAPSHOT ON`, login with `DEFAULT_SCHEMA = dbo` and `db_ddladmin` + `db_datareader` + `db_datawriter`.

### Listing and search (single page: `/artikelen`)
- URL params: `q`, `filterTags` (comma-separated slugs), `tag` (single slug, from tag cards and badges), `status`, `allStatuses`, `page`. The `Suspense` around `ArticleListLoader` is keyed on these, so the skeleton shows on every navigation.
- With `q`: the `search_articles` Postgres function, called from `src/lib/db/repositories/search.ts` with **named arguments** (production still has an older 4-argument overload). It does Dutch full-text search on a generated, weighted `search_vector` (title A, excerpt B, content C) using `websearch_to_tsquery`. Results are capped at 20 and not paginated; equal ranks have no fixed order. `updated_at` is joined from `articles` (`WITH ORDINALITY` keeps the function's order); the function itself is unchanged. On SQL Server `searchArticlesInDb` dispatches to `zoekMssql` instead (see "SQL Server").
- Without `q`: `listArticles` (Kysely). A tag filter uses **AND** semantics via an `id IN (… GROUP BY article_id HAVING COUNT(DISTINCT slug) = n)` subquery; tags for the page come from a second query. Order: pinned first, then `pin_order`, then the user's `default_sort`, then `id`. Pagination fetches `perPage + 1` rows to compute `hasMore` without a count query. Saving an article silently skips tag ids that no longer exist.
- `items_per_page`, `default_sort` and `theme` are per-user preferences on `profiles`. `ThemeSync` applies the theme saved in the database over next-themes' local value.

### Tiptap editor: keep the extension lists in sync
- `src/components/editor/extensions/index.ts` (`editorExtensions`): the editor only. It includes `Placeholder` and a React NodeView for resizable images.
- `src/components/editor/extensions/server.ts`: one factory for `serverExtensions` (print page and email builder; code blocks get inline styles for email clients) and `leesExtensions` (the in-app reading view; no inline styles so the theme applies, lazy images). All callers run on the server and import `generateHTML` from **`@tiptap/html/server`**. The plain `@tiptap/html` export resolves to a browser-only build depending on export conditions (for example under CommonJS). `server.ts` must not import `@tiptap/react`. That is why `resizable-image-server.ts` exists next to `resizable-image.ts`.
- **When you add or change a node or mark extension, update both files.** Otherwise `generateHTML` throws (the reading view then falls back to `content_text`) or drops that content in the reading view, print and email.

### Styling
- Tailwind v4 with CSS-first config in `src/app/globals.css`. There is no `tailwind.config`. Theme tokens are CSS variables (primary `#1A4C58` light, `#FCB50D` dark).
- `@tailwindcss/typography` is **not installed** (it broke the Vercel build), so the `prose` classes in the editor do nothing. Article content styling comes from the hand-written `.ProseMirror` rules in `globals.css`. Add new content styles there, and add print overrides under `@media print` / `.print-light`.

### Uploads and email
- Images (5MB max) and videos (50MB max) go **from the browser straight to storage**: `uploadBestand()` (`src/lib/storage/client-upload.ts`) asks `prepareUpload` (`src/actions/upload.ts`) for a ticket (signed upload URL for the public Supabase buckets `articles` / `avatars`), then uploads with `uploadToSignedUrl`. This avoids the 1MB server-action and 4.5MB Vercel body limits. Avatars are then saved with `finalizeAvatar`. Limits and accepted MIME types are in `src/lib/constants.ts`; the app checks client-declared values, and the buckets enforce the same limits (`file_size_limit` / `allowed_mime_types`, set by `20261017000001_bucket_limits.sql`). Keep both in sync.
- Storage sits behind `StorageDriver` (`src/lib/storage/`): `supabaseStorage`, `databaseStorage` (table `files`, bytea; `varbinary(max)` on SQL Server) or `filesystemStorage` (`STORAGE_DIR`, never overwrites). Path rules live in `paden.ts` (`VEILIG_PAD`, `parseEigenBestandUrl` rejects backslashes/control chars). For database/folder storage, `prepareUpload` returns an HMAC-signed **upload ticket** (`ticket.ts`, 15 min, bound to user, path, type, max size) and the browser POSTs to `/api/bestanden/upload`; files are served (login required) by `/api/bestanden/[...pad]` with Range/206 (max 4 MiB per answer) and ETag. Stored URLs are relative (`/api/bestanden/<bucket>/<path>`). On Vercel, uploads to own storage are capped at 4 MB (function body limit).
- The **"Mailen"** button opens `send-article-dialog.tsx` directly. There is no menu and no `mailto:` option. It sends the full article from the user's **own Google account**, so recipients don't need access to the knowledge base. It uses SMTP with a Google app password (`nodemailer`, `smtp.gmail.com:465`).
  - Each user sets this up under Profiel → E-mail (`/profiel?tab=email`). Saving first runs `verify()` against Gmail. Without a saved setup, the dialog links to that tab instead of showing the form.
  - Credentials live in `mail_settings`, read through the direct DB connection (only the user's own row). In Supabase, RLS is enabled with **no policies** and grants are revoked from anon and authenticated.
  - The app password is stored AES-256-GCM encrypted (`src/lib/crypto.ts`, key `MAIL_ENCRYPTION_KEY`). It is never sent to the browser.
  - `src/lib/email/article-email.ts` builds the HTML. It embeds images as CID attachments: only `data:` URIs and files from our own storage (read via the storage driver, 10 s timeout per image). Images get `width`/`height` capped at 600px, because classic Outlook ignores `max-width`. An own-storage image that can't be embedded becomes a short "niet meegestuurd" note with a link (it would need a login).
- Resend (removed before) needs a verified domain, and the project has none. Gmail per user is the current choice, so don't switch providers without asking.
